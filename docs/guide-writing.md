# 가이드 글 쓰는 규칙 (src/content/guide/*.md)

매일 1편을 쓰는 사람(또는 예약 작업)이 이 문서만 보고 기존 23편과 같은 품질·형식으로 쓸 수 있어야 한다. 먼저 `docs/guide-plan.md`에서 오늘 날짜의 주제를 찾고, 기존 글 2~3편(예: `why-six-month-median.md`, `moving-up.md`, `acquisition-tax.md`)을 읽어 톤을 맞춘다.

## 1. 파일과 머리말(frontmatter)

파일명은 `slug.md` (영문 소문자·하이픈). 스키마는 `src/content.config.ts`가 기준이며 빌드가 검사한다.

```yaml
---
title: "제목 — 부제"                         # 40자 안팎. 숫자·기준이 들어가면 좋다
description: "2~3문장. 무엇을 다루고 무엇을 알게 되는지."  # 검색 결과·목록에 노출
category: price            # situation | loan | tax | price | future (아래 표)
publishAt: "2026-10-21T08:00:00+09:00"   # 그날 08:00 KST
published: true            # 예약 작업이 아침에 쓸 때는 true로 바로 커밋(빌드되면 공개)
asOf: "2026-10-21"         # 글 속 숫자의 기준일(오늘)
facts: []                  # 규칙표 수치 블록을 글 끝에 자동 삽입: didimdol | bogeumjari | bank | acquisition 중 해당하는 것만
cta: calc                  # calc(계산기) | find(집 찾기) | ref(레퍼런스) | none
situation: first           # cta가 calc일 때만, 해당되면: first | newly | youth | general | move
related: [slug1, slug2]    # 기존 가이드 slug 2~3개(실제로 존재해야 함)
sources:
  - { title: "기관명 — 문서명", url: "https://…", date: "YYYY-MM-DD" }   # 공식 출처만, 2개 이상
---
```

| category | 이름 | 어떤 글 |
|---|---|---|
| situation | 상황별 집 사기 | 절차·실무·내 상황에서 받을 수 있는 것 |
| loan | 대출 상품 공부 | 자격·한도·금리·상환 |
| tax | 세금·부대비용 | 취득·보유·양도세, 증여, 비용 |
| price | 시세 읽는 법 | 실거래·지수·통계·단지 데이터 읽기, 쏙집 기능 설명 |
| future | 호재·정비사업 | 교통·정비사업·분양 — 사실과 일정만 |

## 2. 분량과 구조 — "한눈에 들어오게"

독자는 폰으로 읽는다. 문단으로 설명하기 전에 **표로 보여 주고, 글은 그 표의 이유를 설명**한다. 표·정의 박스·번호 목록은 사이트가 토스식 카드 모양으로 자동 꾸민다(`src/pages/guide/[slug]/index.astro`).

- 본문 **공백 포함 4,000~6,000자**, 문단은 3문장 이내. 숫자·요건·일정은 표에, 이유·맥락은 글에.
- 첫 문단은 제목 없이 2~3문장: 왜 읽는지 + 이 글이 답하는 것.
- **`## 한눈에 보기`** — 첫 문단 바로 다음에 반드시 넣는다. 머리글 `| 항목 | 내용 |` 2열, 3~5줄: 무엇인지 / 누가 해당 / 금액·기간·기준 / 어디서 확인. 결론 값은 `**굵게**`(파랑으로 표시됨). 이 제목(정확히 "한눈에 보기")의 바로 다음 표가 라벨|값 카드로 렌더된다.
- **병렬 항목이 3개 이상이면 표**로 쓴다 — 비교·구간·요건·일정·판결. 글당 표 4~6개 목표.
  - 열은 **3개 이하 권장**(폰 폭에 들어감). 4열은 꼭 필요할 때만 — 폰에서는 카드 안에서 옆으로 밀어 보게 되고 "옆으로 밀어서 보기" 안내가 붙는다. 5열 이상 금지.
  - 머리글 행 필수. 첫 열은 행의 이름(자동으로 굵게), 셀 안 결론 한 단어는 `**굵게**`.
  - 표 바로 위 문장이 표의 캡션 역할을 한다("…세 가지는 다음입니다.").
  - 절차 글은 **단계 표**(단계 | 할 일 | 확인할 것·근거), 확인 글은 **체크리스트 표**(확인할 것 | 왜 | 어디에 남기나·근거).
- `##` 소제목 5~8개, 결론형으로("성립 안 했으면 — 원칙은 반환입니다"). 필요하면 `###`.
- 정의는 `>` 인용 블록 한 줄(연파랑 정의 박스로 렌더). 글당 1~2개.
- 번호 목록(`1.`)은 순서가 있는 행동에만(동그라미 번호 카드로 렌더). 병렬 나열은 표 또는 글머리표.
- 마지막 소제목은 항상 `## 정리` — `| 핵심 | 내용 |` 표 3줄 + 다음 행동(쏙집 기능 링크) 한 문장.
- 쏙집 기능으로 이어지는 링크를 본문에 1~3개: `/calc/`, `/find/`, `/area/`, `/ref/`, `/compare/`, 다른 가이드 `/guide/slug/`. 링크 문구는 기능 이름으로.
- 본보기: `provisional-deposit.md`(가계약금) — 한눈에 보기, 3열 표, 4열 표, 체크리스트 표, 단계 카드, 정리 표가 모두 들어 있다.

## 3. 문장 규칙 (반드시)

- **존댓말("~입니다", "~하세요")**. 담담하고 구체적으로. 감탄·과장·호객 문구 없음.
- **판단·추천 금지**: "이 지역이 낫다", "지금 사야", "추천", "유리하다/불리하다"로 결론 내지 않는다. 사실·수치·절차·기준과 출처만 쓴다. "~일 수 있습니다", "~인 경우가 많습니다"처럼 조건을 붙인 설명은 가능하다.
- **가격 전망 금지**. 과거 기록은 쓰되 "오를/내릴 것"은 쓰지 않는다. 지수·변동률 글은 "지난 1년의 기록이지 앞으로의 방향이 아닙니다"를 밝힌다.
- **모든 숫자에는 기준과 출처**: 금액·요율·한도·일정은 "2026년 10월 기준", "○○법 시행령 제n조" 등 근거를 문장 안에 쓰고 `sources`에 URL을 넣는다. 출처를 못 찾은 수치는 쓰지 않는다(추정 금지).
- 대출·세금 수치는 먼저 **규칙표 `data/rules/` 최신 버전**을 본다. 규칙표에 있는 값은 그 값과 일치해야 하고, 없는 값은 공식 출처(국세청·국토교통부·주택도시기금·한국주택금융공사·법제처 law.go.kr·한국부동산원·금융위원회)에서 확인한다. 민간 사이트(네이버 부동산·호갱노노 등)와 블로그는 출처로 쓰지 않는다.
- 법령·제도는 **시행일**을 적는다. 개정 예정은 "예정"이라고 쓰고 확정된 것과 구분한다.
- 쏙집 데이터의 정의는 바꾸지 않는다: 시세 = 같은 단지·같은 평형 최근 6개월 실거래 중앙값(해제·직거래 제외), 1년 변동률 = 6개월 중앙값 vs 1년 전 같은 6개월(두 기간 3건 이상), 지역 변동률 = 평형별 변동률의 중앙값(10개 미만이면 표본 부족), 부동산원 지수 "1년" = 52주 전 대비, "N주째" = 전주 대비 연속 주 수. 사이트 현재 수치가 필요하면 `npm run build` 뒤 `data/index/summary.json`에서 읽고 기준일을 같이 적는다.
- **머니프리덤·korea-rich.kr 브랜드를 쓰지 않는다.** 사이트 이름은 "쏙집".
- 사람·업체 실명, 특정 단지의 호재 단정, 특정 상품 권유는 쓰지 않는다. 단지를 예로 들 때는 데이터(실거래)로 확인되는 사실만.
- 존재하지 않는 페이지로 링크하지 않는다(`related`의 slug와 본문 링크는 실제 파일·경로를 확인).

## 4. 쓰는 순서

1. `docs/guide-plan.md`에서 오늘 주제 확인. 이미 같은 날짜 글이 `src/content/guide/`에 있으면 중복 작성하지 않는다.
2. 기존 글 중 가까운 주제 2편을 읽어 겹치는 내용은 링크로 넘기고 새로 다룰 범위를 정한다.
3. 출처 조사(공식 문서·법령·통계). 수치는 원문에서 확인해 기준일과 함께 메모.
4. 집필 → 머리말 작성 → `related`·링크 경로 존재 확인.
5. `npm run build`가 통과해야 한다(스키마·링크 오류는 여기서 잡힌다).
6. `docs/guide-plan.md`의 해당 행 `상태`를 `완료(slug)`로 바꾼다.
7. 커밋 메시지: `글 발행: {제목}` 한 줄. 푸시하면 Cloudflare가 빌드해 공개된다(약 4분).

## 5. 하지 않는 것

- 같은 날 2편 이상 쓰지 않는다(하루 1편).
- 계획표 밖의 주제를 임의로 쓰지 않는다. 주제가 더는 맞지 않으면(제도 폐지 등) 쓰지 말고 운영자에게 알린다.
- 글 외의 파일(규칙표·컴포넌트·설정)을 고치지 않는다.
