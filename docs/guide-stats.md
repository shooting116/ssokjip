# 이달의 통계 글 쓰는 규칙 (category: stats)

매달 나오는 공식 통계 발표를 **숫자 그대로** 옮겨 적는 글이다. 매일 1편 쓰는 계획표 글(`docs/guide-plan.md`)과는 별도이며, 같은 날 계획표 글이 이미 올라갔어도 쓴다. 문장 규칙·표 규칙·머리말 스키마는 `docs/guide-writing.md`를 그대로 따르고, 아래는 통계 글에만 해당하는 차이다.

## 1. 대상 통계 (이 둘만)

| 통계 | 발표 기관 | 보도자료 제목 모양 | 나오는 때 | slug |
|---|---|---|---|---|
| 가계대출 동향 | 금융위원회·금융감독원 | `YYYY년 M월 가계대출 동향(잠정)` | 다음 달 둘째 주 무렵 | `stats-household-loans-YYYY-MM` |
| 주택통계 | 국토교통부 | `YYYY년 M월 주택통계` (또는 `M월 주택 통계 발표`) | 다음 달 말일 무렵 | `stats-housing-YYYY-MM` |

- slug의 `YYYY-MM`은 발표일이 아니라 **통계의 기준 월**이다(10월 가계대출 동향 → `2026-10`).
- 목록에서 찾는 곳: 정책브리핑 부처별 보도자료 — 금융위 `https://www.korea.kr/briefing/pressReleaseList.do?repCodeType=A&repCode=C00003`, 국토부 `…&repCode=A00006`.
- 그 slug의 파일이 `src/content/guide/`에 이미 있으면 쓰지 않는다. 가장 최근 기준 월 1건만 쓰고, 지나간 달을 소급해 쓰지 않는다.
- 표에 없는 통계(부동산원 주간 동향, 한은 금융시장 동향 등)는 쓰지 않는다. 늘리려면 운영자가 이 표에 먼저 추가한다.

## 2. 숫자를 가져오는 곳

1. 보도자료 **원문 본문**에서만 가져온다. 순서: 정책브리핑(korea.kr) 본문 → 기관 누리집(fsc.go.kr, molit.go.kr) 보도자료 → KDI 경제교육·정보센터(eiec.kdi.re.kr) 게재본.
2. 원문에서 직접 확인하지 못한 숫자는 쓰지 않는다. 언론 기사는 원문을 찾는 실마리로만 쓰고 `sources`에 넣지 않는다.
3. 원문을 끝내 읽지 못하면 글을 쓰지 않고 "원문 확인 불가"로 알린다(다음 실행에서 다시 시도된다).
4. 전월·전년 동월 수치는 같은 보도자료의 표에서 가져온다. 지난달 쏙집 글의 숫자와 다르면(잠정치가 확정되며 바뀜) 이번 보도자료 숫자를 쓰고 그 사실을 한 줄로 적는다.

## 3. 머리말

```yaml
title: "2026년 10월 가계대출 동향 — 전 금융권 +6.4조 원, 주담대 +4.0조 원"   # 기준 월 + 핵심 숫자 2개
description: "…"            # 2~3문장. 무엇이 얼마였는지 숫자로
category: stats
publishAt: "발표를 쓴 날T13:00:00+09:00"
published: true
asOf: "쓴 날"
facts: []
cta: none
related: [직전 달 같은 통계 글(있으면), 관련 가이드 1~2개]   # 예: 가계대출 → ltv-dsr-dti, 주택통계 → unsold-stats·supply-pipeline·volume-and-price
sources:                    # 공식 출처만. 보도자료 원문 1개는 반드시
```

## 4. 분량과 구조

본문 공백 포함 **2,500~4,000자**. 표 3~5개.

1. 첫 문단(제목 없이 2~3문장): 어떤 통계의 몇 월분이 언제 발표됐는지, 핵심 숫자.
2. `## 한눈에 보기` — `| 항목 | 내용 |` 4~5줄(통계 이름·기준 월 / 핵심 숫자 / 전월 대비 / 발표 기관·발표일 / 잠정치 여부).
3. `## 이번 달 숫자` — 항목별 표(이번 달 | 전월 | 전년 동월, 3~4열). 가계대출은 주담대·기타대출과 은행·2금융권, 주택통계는 인허가·착공·분양·준공·미분양·준공 후 미분양·매매 거래량·전월세 거래량을 원문에 있는 만큼.
4. `## 지난 몇 달과 나란히` — 원문 표에 있는 최근 3~6개월 흐름. 원문에 없으면 이 절을 뺀다.
5. `## 이 숫자가 세는 것` — 용어 정의(`>` 정의 박스 1~2개)와 집계 범위. 겹치는 설명은 기존 가이드 링크로 넘긴다.
6. `## 발표 기관의 설명` — 기관이 보도자료에서 밝힌 평가·향후 방침을 "금융위는 …라고 밝혔습니다"로 **인용 서술만**. 원문에 없으면 뺀다.
7. `## 읽을 때 확인할 점` — 잠정치, 전월 대비와 전년 대비의 차이, 계절성 등 읽는 법(체크리스트 표).
8. `## 정리` — `| 핵심 | 내용 |` 3줄 + 쏙집 기능 링크 한 문장.

## 5. 문장 — 통계 글에서 특히

- "늘었다/줄었다/전환했다"처럼 **사실 서술만**. "급증", "폭증", "과열", "위험", "안정" 같은 평가 낱말을 쓰지 않는다.
- 왜 늘었는지의 해석, 집값·금리·규제의 앞으로 방향은 쓰지 않는다. 원인 설명이 필요하면 기관 설명을 인용으로만 옮긴다.
- 대출 규제가 바뀐다는 내용이 보도자료에 있으면 글에는 "발표 내용"으로만 적고, 규칙표(`data/rules/`)는 고치지 않는다. 카카오톡 알림에 "⚠️규칙 변경 내용 포함"을 붙인다.
- 금지 표현 점검: "추천", "지금 사야", "유리", "불리", "오를 것", "내릴 것", "급증", "폭증", "과열".

## 6. 올리기

- 바꾸는 파일은 새 글 1개뿐이다(계획표는 건드리지 않는다). `npm run build` 통과 → 커밋 `통계 글 발행: {제목}` → `git pull --rebase origin main` → `git push origin HEAD:main`.
- 운영자 확인 없이 바로 공개한다(2026-11-12 운영자 결정). 공개 뒤 카카오톡으로 한 통 알린다.
